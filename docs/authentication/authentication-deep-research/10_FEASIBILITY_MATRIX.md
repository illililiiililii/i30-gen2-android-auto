# 10. 실현 경로 판정 매트릭스

작성: 2026-11-25 · 원칙: **성공 확률 수치를 만들지 않는다.** 조건과 판정만 기록한다.

## 1. 목표 정의별 가능성

사용자 목표: "GD13MY 순정 펌웨어에서 **순정 Google Android Auto**를, 폰 측 앱·루트·외부 수신기·동글 없이 실행"

| 목표 변형 | GAL 신원 필요 | 현재 가능 | 막는 것 |
| --- | --- | --- | --- |
| A. 순정 AA 앱 + 순정 폰 + 자체 수신기 | **필요** | **불가** | 신원 미확보 |
| B. A + 상용 SDK 라이선스 | 필요(벤더가 보유) | 미확인 | WinCE 6.0 지원, 계약 |
| C. 순정 AA 앱 + 자체 폰 앱(AARE 방식) | 불필요 | 가능 | "폰 앱 없음" 조건 위반 |
| D. 순정 AA 앱 + 동글/외부 수신기 | 불필요(동글이 처리) | 가능 | "동글 없음" 조건 위반 |
| E. 순정 펌웨어 신원 재사용 | — | **불가** | 신원 자체가 없음(§07) |

⇒ A는 **단일 조건(신원)** 에서 막혀 있고, 그 조건은 코드로 해결되지 않는다.

## 2. 경로별 상세 판정

### 경로 A-1: 자체 생성/자체 서명 신원
- 시도 이력: 있음(다수). 결과: `Trust anchor for certification path not found`.
- 외부 독립 재현: pi-auto-headunit (2026-08) 동일.
- 판정: **FAILED (확정)**. 재시도 금지.

### 경로 A-2: 공개된 GAL 발급 인증서 재사용 (DHU/AASDK/LIVI)
- 기술: 체인 검증 통과(§03). 실사용 사례 존재.
- 문제: Google 내부/타사 신원 위장.
- 판정: **금지 (정책)**. 기술적 성공과 별개.

### 경로 A-3: 상용 SDK (Cinemo/ART/ECORE/NXP)
- 조건: ①WinCE 6.0 또는 ARMv7 Linux 지원 ②평가용 신원 ③GPL 분리 배포 ④비용
- 현재: ①미확인 ②미확인 ③미확인 ④미확인
- 판정: **PARTIAL (대기)**. 문의 재발송 금지.

### 경로 A-4: Google 파트너/인증
- 조건: 제품 단위 AAP 인증, 3PL 파트너 경유
- 현재: 개인 프로젝트 진입 경로 공개 없음
- 판정: **UNKNOWN → 사실상 불가**

### 경로 B: 목표 재정의 (자체 폰 앱)
- 필요: 폰 측 앱 설치 허용
- 판정: **가능하나 요구사항 위반**

## 3. 의사결정 트리

```
[신원 확보 되었는가?]
├─ 예 → [체인 구성이 leaf-only인가?]
│        ├─ 예 → [게스트 UTC가 유효기간 내인가?]
│        │        ├─ 예 → 실폰 시험 → AUTH_COMPLETE 기대
│        │        └─ 아니오 → 시계 설정 후 재시험 (§08 1.4)
│        └─ 아니오 → leaf만 남기고 재시험 (§08 1.3)
└─ 아니오 → [상용 SDK가 WinCE 6.0 + 평가 신원을 제공하는가?]
           ├─ 예 → 라이선스 협의 → 통합 검토
           ├─ 미확인 → 대기 (문의 1회 완료)
           └─ 아니오 → [목표 재정의 수용?]
                      ├─ 예 → AARE형 자체 폰 앱 경로
                      └─ 아니오 → 프로젝트 종료(실패 기록 확정)
```

이 트리는 "지금 할 수 있는 일"과 "기다려야 하는 일"을 분리한다.

## 5. 하지 않을 것

- 자체 서명 신원으로 실폰 재시도 (이미 반증)
- DHU/AASDK/LIVI 개인키 사용
- BearSSL 전체 교체 (실패 원인 아님)
- 성공 확률 추정치 제시
- Cinemo 재문의
- `G:\` 원본 수정
