# Phase 6 벽돌 위험과 복구 조건

GD13MY 덤프에서 X-Loader와 EBOOT 흔적, 독립 CE 커널과 MICOM, `install.ini`의 영역별 항목, `AVNRecovery.exe` 후보 경로가 확인됐다. SHA-256으로 대조한 순정 배포 파일을 보유하고 있다. 이 본체에서의 실제 쓰기 순서, 중단 후 재개 기능, 이미지 인증 정책, 저장매체 상태, 독립 복구 도구는 아직 검증되지 않았다. [펌웨어 패키징 감사](FIRMWARE_PACKAGING.md) · [순정 부트·복구 자료](DEEP_REVERSE_ENGINEERING.md)

**벽돌 확률: 정량 추정 불가.** 모든 작업에 동일한 판정을 적용한다. 해당 HW 리비전의 분모가 있는 실측 결과, 장애별 기록, 독립적인 복구 성공률이 없다. 아래 등급은 실패 시 영향을 받을 수 있는 영역과 복구 경로에 기반한 정성 평가다. 소프트 브릭은 검증된 복구 경로로 정상 부팅을 회복할 수 있는 상태다. 하드 브릭은 일반 경로를 잃어 전문 하드웨어 복구가 필요한 상태다. 실제 장애에 검증된 복구 경로가 없으면 소프트 브릭으로 단정할 수 없다.

## 작업별 위험

| 작업 | 소프트 브릭 | 하드 브릭 | 근거, 최악의 결과, 복구 조건 |
|---|---|---|---|
| 순정 부팅 및 설정 확인 | 낮음 | 낮음 | 확인한 보호 하네스로 정상 부팅하고 화면 값을 읽는 작업이다. 전기적 연결을 틀리면 영구 손상이 가능하므로 이 등급은 확인된 전원·단자를 전제한다. 순정 상태 재부팅이 기준이며, 전기적 장애 시 정비 점검이 필요하다. |
| 읽기 전용 진단 | 낮음 | 낮음 | 공식 진단 세션과 기록 조회만 수행한다. 세션이 응답하지 않으면 정상 종료 절차로 복귀하고 로그를 보존한다. 보호되지 않은 어댑터를 임의로 연결했을 때의 손상은 이 범위에 포함되지 않는다. |
| 승인된 독립 진단 앱 | 중간 | 낮음 | 사용자 모드에서 일시 멈춤이나 순정 UI 이상이 가능하다. 자동 시작·레지스트리·OEM 파일을 건드리지 않는 probe가 대상이다. 종료/정상 재부팅으로 복구가 되는지 확인하고 실패 시 중단한다. |
| 사용자 영역 파일 변경 | 중간 | 낮음 | 실제로 비부팅 영역임이 확인됐을 때의 등급이다. 오인한 경로 또는 저장장치 쓰기 실패는 UI 부팅 반복이나 데이터 손실을 유발할 수 있다. 확실한 파일 백업과 앱 부팅 실패 상태에서도 가능한 공식 복원 경로가 필요하다. |
| OS 구성 요소 변경 | 높음 | 높음 | CE 커널·드라이버 불일치가 파일시스템, 디스플레이, 복구 프로그램 실행까지 막을 수 있다. OS에 의존하지 않고 해당 이미지를 복구하는 검증된 경로가 필요하다. |
| 커스텀 펌웨어 업데이트 | 높음 | 매우 높음 | 실패 영역이 APP·BSP·저장매체·MICOM까지 넓다. 적용 순서와 중단 시 원자성, 검증 정책을 확인하지 못했다. 호환성·정상 복구·무부팅 복구를 모두 입증하기 전에는 실행할 수 있는 것으로 판단하지 않는다. |
| 부트로더 및 복구 영역 변경 | 매우 높음 | 매우 높음 | 초기 로더와 유일한 복구 경로를 함께 잃을 수 있다. 외부 기록 장비와 동일 리비전의 온전한 복구 자료를 가진 전문 서비스가 필요하며, 보드 교체가 최악의 결과다. |

정성 평가의 신뢰도는 업데이트 중 전원 차단, 로더 손실 같은 일반 실패 메커니즘에서 중간이다. GD13MY의 실제 실패 빈도, 실패 후 재시도 가능 여부, 영역별 등급 경계의 신뢰도는 낮다. [현대 업데이트 유의사항](https://update.hyundai.com/RU/KO/updateGuide/04)

## 업데이트 실패 원인별 평가

| 위험 요인 | 예상 장애와 판단 |
|---|---|
| 전원 차단·업데이트 매체 제거 | 진행 중인 영역이 불완전할 수 있다. APP이면 독립 복구가 확인될 때 소프트 브릭으로 회복할 수 있지만, 부트 영역이면 하드 브릭 가능성이 커진다. 실제 적용 순서는 미검증이다. |
| 모델·HW 리비전 불일치 | 정확한 본체/리비전 대조 전에는 공급 전원과 이미지 모두 승인할 수 없다. 접두사나 차종만 맞아도 BSP·MICOM·저장 영역이 다를 수 있다. 초기화 실패, 화면 무응답, 복구 경로 손실로 이어질 수 있다. |
| 파일 손상 | 배포본의 CRC32/MD5가 불일치를 감지할 수 있다. 기기에서 첫 쓰기 전에 모든 항목을 검사하는지와 부분 쓰기 발생 시점은 미확인이다. 해시가 다른 파일은 쓰기 전에 격리한다. |
| 서명·인증 거부 | 실패 원인을 기록하고 공식 도구와 정확한 패키지를 확인한다. PE 인증서 테이블이 비어 있어도 기기의 외부 인증 또는 부팅 정책은 별개다. 거부가 쓰기 전에 발생하는지는 실기기 로그가 필요하다. |
| 부트로더·OS 이미지 손상 | 부트로더 손상은 일반 복구 진입 자체를 막을 수 있다. OS 차원의 손상은 독립 복구가 동작하는 경우에만 소프트 브릭으로 되돌릴 수 있다. |
| 드라이버 호환성 | 화면·오디오·USB·저장장치가 초기화되지 않을 수 있다. 해당 드라이버를 복구 도구도 쓰면 서비스 매체 접근을 잃을 수 있다. |
| 저장장치 쓰기 실패 | 노후 매체, 용량·영역 문제의 징후는 쓰기 전 검사 단계에서 다룬다. 실패 장치를 반복해서 쓰면 원래 데이터를 보존하기 어려워진다. 원본 로그와 파일을 남기고 저장장치 진단으로 전환한다. |
| 복구 모드 진입 실패 | 전원과 정상 진입 조건을 확인하고, 신뢰할 수 있는 독립 경로와 지원 서비스가 없다면 반복 쓰기를 중단한다. 단순히 순정 파일을 갖고 있다는 사실은 복구 성공을 보장하지 않는다. |

## 변경 승인 전에 확인할 복구 범위

1. 대상 본체 부품 번호·HW 리비전·현재 SW와 복구 자료의 대응을 기록한다. 검증한 순정 파일과 해시 목록을 보존한다.
2. 부팅 정상, APP 실패, OS 부팅 불가를 구분해 각각 제조사 지원 진입 조건과 필요한 장비·매체를 확인한다. 동일 리비전에서 순정 부팅으로 복귀했다는 서비스 근거 또는 벤치 실측을 확보한다.
3. 가능한 복구에 포함되는 APP·BSP·MICOM·부트 영역과 포함되지 않는 영역을 기록한다. 복구 장비와 작업자가 실제로 준비되어 있어야 한다.
4. 위 자료가 확보되기 전에는 순정 부팅, 읽기 전용 진단과 승인된 독립 probe까지만 진행한다. 실제 펌웨어 수정과 설치는 보류한다. [실물 순서와 중단 조건](PHASE6_BENCH_TEST_GUIDE.md)
