# 타당성 판정

**현 시점은 D · 실물 검증까지 구현 보류.** 펌웨어의 USB 호스트, ARM용 Windows Embedded CE 6.0, 화면·오디오·터치 드라이버는 접근 가능성을 보여 준다. Android Auto 요구사항 중 실물에서 통과한 항목은 아직 없다.

| 방안 | 판단 |
|---|---|
| A · 기존 수신기 포팅 | OpenAuto와 OpenHU의 호스트 앱은 CE OMAP 표적을 제공하지 않는다. aasdk도 USB 및 C++ 의존성 변경과 미디어 어댑터 작성이 필요하다. PC 기준 구현으로 사용한다. |
| B · 기존 CE용 경량 수신기 | 검증을 계속할 경우 가장 유망하다. USB와 디코더가 필수다. 작게 시작하면 CE에서 신규 드라이버, 메모리 및 런타임 부담을 실측할 수 있고 OEM UI와 하드웨어 드라이버의 통합도 유지할 수 있다. |
| C · OS 또는 런타임 확장 | OMAP3530 플랫폼 자체의 OS 지원과 이 보드의 부팅, 터치, USB, 오디오, 카메라, MCU 드라이버 지원은 각각 별개다. CE의 기능 한계가 확인될 때 제한된 런타임 추가부터 고려한다. OS 교체를 뒷받침할 보드 자료와 통합 경로는 현재 없다. |
| D · 보류 | 실물 식별, 현행 OEM 시스템에서 허용되는 실행·설치 경로, AOA bulk 접근, 영상 스트림 성능을 검증할 때까지 적용한다. 이 중 하나라도 충족할 수 없으면 순정 하드웨어만 사용하는 범위에서는 보류를 유지한다. |

초기 우선순위는 **기기 식별 및 실행 경로 → USB AOA → H.264 및 화면 자원 → 오디오·입력·순정 기능 복귀**다. 순정 카메라 우선권과 케이블 제거 시의 복구는 출시 여부를 가르는 조건이다. 컴파일 시간에 정의된 19 MiB RAM 범위와 해시 기반 무결성 필드로 실물 여유 메모리 및 보안 부팅 상태를 판단할 수 없다.
