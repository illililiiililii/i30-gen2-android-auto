# Phase 6 벤치 검증 계획

에뮬레이션 우선 확인 이후 현재 실행 순서와 중단 조건은 [Phase 6 실물 벤치 가이드](PHASE6_BENCH_TEST_GUIDE.md)에 있다. [준비 상태](PHASE6_READINESS_REPORT.md)

Phase 5에서 생성한 진단 PE와 읽기 전용 검증 도구를 기준으로 실물 검증에 진입할 수 있다. 첫 실물 단계는 본체 식별, 복구 경로 확인, 승인된 진단 앱 실행이다.

1. **기기 식별과 기준 측정.** 본체 라벨, HW 리비전, 현재 순정 SW, 전원·USB·카메라·오디오 하네스를 기록하고 GD13MY 패키지와 맞춘다. 순정 부팅, 카메라 전환 시간, 라디오·미디어·차량 경고, 마이크 등 비교 기준을 수집한다.
2. **복구와 정상 진단 앱 진입.** 제조사가 지원하는 진단 앱 로딩 및 복구 절차를 확인한다. 정상적인 실행 경로에서 독립 CE probe를 실행하고 시작·디버그 로그·파일·힙·스레드·종료 결과를 확인한다. 복구 성공 조건을 독립적으로 확인하기 전에는 업데이트 실험을 보류한다.
3. **USB와 수신기.** 승인된 USB 드라이버 접근으로 열거, AOA 송수신, 분리 시 리소스 반환을 확인한다. 이후 등록된 테스트 자격으로 TLS 성공과 실패 시 정상 복구, 서비스 탐색 순으로 진행한다.
4. **영상·오디오·입력 연동.** 대상 영상 디코더와 표면에서 800×480·30fps를 검증한다. 라디오·경고음·ASR과 자원 소유권이 충돌하거나 회수될 때 결과를 확인한다. 실물 버튼 코드를 벤치에서 관찰하고 차량 안전 입력을 순정 경로에 유지한다.
5. **OEM 우선권과 복구.** 후방카메라·주차 화면·경고를 표시 상태마다 유발하고 Phase 6의 순정 기준 시간과 비교한다. USB 분리, 정상 종료, 크래시, 응답 지연 후 OEM 화면·입력·오디오 반환까지 기록한다.
6. **후속 최적화 및 패키징 판단.** 장시간 시험은 후속 최적화 단계에서 CPU·메모리·온도·프레임·안내음 지연을 측정할 때 사용한다. OEM 설치 정책과 복구를 검증한 뒤 업데이트 패키지 통합 가능 여부를 판단한다. [기존 상세 벤치 기준](PHASE2_IMPLEMENTATION_PLAN.md) · [패키징 감사](FIRMWARE_PACKAGING.md)
